# مكتبة المؤلف الأدبية — المكتبة الرقمية الخاصة بالمؤلف

موقع إلكتروني متكامل بواجهة عربية (RTL) بمستوى الإنتاج، يمثل **مكتبة أدبية رقمية فاخرة** خاصة بمؤلف واحد: رفوف كتب خشبية بإضاءة دافئة، هوية بصرية فحمية وذهبية وعاجية، لوحة إدارة محمية («لوحة المطوّر»)، وواجهة قراء نظيفة — **فارغ تمامًا من أي محتوى تجريبي وجاهز للنشر الفعلي من اليوم الأول**.

يعمل المشروع بوضعين بنفس الكود: قاعدة SQLite محلية وملفات على القرص للتطوير، وقاعدة **Turso** السحابية وتخزين **Cloudflare R2** للإنتاج — والتحويل بينهما يتم من متغيرات البيئة وحدها دون تغيير أي سطر في الكود. دليل النشر المجاني الكامل في قسم [النشر الدائم المجاني خطوة بخطوة](#النشر-الدائم-المجاني-خطوة-بخطوة-github--turso--r2--vercel).

## المزايا

### واجهة القراء
- واجهة عربية كاملة بدعم RTL صحيح، ووضع داكن هو المظهر الأساسي (أسود فحمي `#101010`، ذهبي هادئ `#C6A15B`، أبيض عاجي `#F4EFE5`).
- خطوط عربية أدبية: **IBM Plex Sans Arabic** للواجهة و**Noto Naskh Arabic** للعناوين الأدبية.
- صفحة رئيسية تبدو كمكتبة حقيقية: مشهد رفوف فني، إبراز «إصدار مميز»، رفوف لكل تصنيف، ورف فني فارغ أنيق عند غياب الكتب مع رسالة قابلة للتعديل («ستجد هنا إصدارات المكتبة قريبًا»).
- تصفح «المكتبة»: بحث (عنوان/مؤلف/كلمات مفتاحية/تصنيف)، تصفية بحالة الإصدار (متوفر/قادم/غير متوفر)، ترتيب، وتبديل العرض بين **رفوف** و**شبكة أغلفة** بتأثيرات خفيفة.
- صفحة مستقلة لكل كتاب: غلاف، غلاف كامل، نبذة ووصف تفصيلي، تصنيف، صفحات، سنة، ISBN، ناشر، حالة، سعر وعملة (عند تفعيل البيع)، معرض صور، طلب/شراء، مشاركة اجتماعية، مفضلة، قراءة PDF داخل الموقع (عند إتاحتها)، وكتب ذات صلة.
- صفحات: عن المؤلف، تواصل (نموذج يحفظ الرسائل في لوحة الإدارة)، الأسئلة الشائعة (أكورديون)، سياسة الخصوصية، شروط الاستخدام، سياسة البيع والاسترجاع — كلها قابلة للتحرير من اللوحة.
- حساب القارئ (ميزة قابلة للتفعيل/التعطيل): مفضلة، سجل الطلبات، تعديل البيانات، وحذف الحساب. **التسجيل ليس شرطًا للتصفح.**
- صفحة 404 أدبية، تصميم متجاوب كامل (جوال/لوحي/كمبيوتر)، فوتر ثابت أسفل الشاشة.

### لوحة المطوّر (الإدارة)
- تسجيل دخول محمي + **تهيئة آمنة لأول حساب مالك** تعمل فقط عند خلو قاعدة البيانات من المستخدمين.
- لوحة تحكم: إجمالي المنشور/المسودات/المجدولة، الزيارات (عند تفعيل التحليلات)، الطلبات والمبيعات (عند تفعيل المتجر)، رسائل غير مقروءة، وآخر العمليات — **بحالات فارغة صادقة دون أرقام وهمية**.
- إدارة الكتب كاملة: إضافة/تعديل/حذف (بتأكيد)، مسودة، نشر فوري، **جدولة بتاريخ ووقت** (نشر تلقائي كسول عند حلول الموعد)، إلغاء النشر، **معاينة قبل النشر**، ترتيب يدوي على الرفوف (أسهم أعلى/أسفل)، رفع الغلاف والغلاف الكامل وصور إضافية وملف PDF مع التحكم في القراءة والتنزيل، ISBN/السعر/العملة/الناشر، ووسوم وSEO لكل كتاب.
- تصنيفات (مع اقتراحات إضافة سريعة) ووسوم، مكتبة ملفات (بحث/تصفية/كتب مرتبطة/خصوصية)، إدارة الصفحات، الطلبات (حالات + تأكيد دفع يدوي بعد تحقق فعلي)، رسائل التواصل، المستخدمون والأدوار (المالك/محرر/قارئ)، سجل العمليات الإدارية، وإعدادات الموقع الكاملة (الاسم، الشعار، المؤلف، النبذة، البورتريه، النصوص، **الألوان الأساسية**، التواصل والسوشال، تفعيل المتجر/التسجيل/التحليلات، العملة، SEO).

### المتجر
- بنية قابلة للتفعيل لاحقًا (معطلة افتراضيًا): سعر لكل كتاب وعملة (دعم **الدينار الكويتي** KWD وغيرها)، طلب ورقي/رقمي، نموذج طلب بالحد الأدنى من البيانات، حالات الطلب (جديد/قيد المعالجة/مكتمل/ملغى)، سجل وإشعارات بالطلبات الجديدة (شارة في اللوحة).
- **لا دفع وهميًا**: الطلب يبدأ «جديدًا غير مدفوع»، ولا يوسم «مدفوع» إلا بتأكيد يدوي من المالك بعد تحقق فعلي من مزوّد الدفع. عند غياب بوابة دفع مربوطة يظهر إشعار واضح للزائر مع وسيلة تواصل بديلة.

## الحزمة التقنية

| الطبقة | التقنية |
|---|---|
| الإطار | Next.js 16 (App Router) + TypeScript 5 |
| الواجهة | React 19 + Tailwind CSS 4 + shadcn/ui (New York) + Lucide + Sonner |
| الخادم | Next.js Route Handlers (REST API) |
| قاعدة البيانات | Prisma ORM + SQLite — ملف محلي أو **Turso** سحابيًا عبر `@prisma/adapter-libsql` (وضعان بنفس المخطط) |
| المصادقة | جلسات مخزنة في القاعدة + كوكي httpOnly + تشفير كلمات المرور بـ scrypt |
| تخزين الملفات | القرص المحلي (`private-uploads/`) أو **Cloudflare R2** (متوافق S3) — يُخدَم دائمًا عبر API بصلاحيات |
| الاستضافة | Vercel (خطة Hobby المجانية) أو أي خادم Node/Bun (نسخة standalone) |

## التشغيل محليًا

```bash
# 1) المتطلبات: Node.js 20+ أو Bun 1.1+
bun install            # أو npm install

# 2) جهّز متغيرات البيئة: انسخ النموذج الرسمي ثم املأ القيم
cp .env.example .env
#    محليًا يكفي ضبط سطرين:
#    DATABASE_URL="file:/المسار-المطلق-للمشروع/db/custom.db"
#    SESSION_SECRET="ناتج الأمر: openssl rand -hex 32"

# 3) أنشئ جداول قاعدة البيانات المحلية
bun run db:push

# 4) شغّل خادم التطوير
bun run dev            # http://localhost:3000

# 5) فحص الجودة
bun run lint
```

- في التطوير المحلي تُخزَّن الملفات المرفوعة تلقائيًا في مجلد `private-uploads/` — لا حاجة لأي إعداد سحابي، لأن متغيرات `S3_*` فارغة (انظر [متغيرات البيئة](#متغيرات-البيئة-المرجع-الكامل)).
- ملاحظة عن البنية: كل الواجهة تعمل من المسار العام `/` بتوجيه داخلي (`#/book/…`)، مع روابط مشاركة قابلة للفهرسة بالصيغة `/?book=slug` تُولّد بياناتها الوصفية من الخادم (عنوان/وصف/Open Graph). خريطة الموقع `sitemap.xml` و`robots.txt` تُولّدان تلقائيًا.

## متغيرات البيئة (المرجع الكامل)

الأسماء أدناه **مطابقة حرفيًا لملف `.env.example`** — انسخه إلى `.env` محليًا، وأدخل القيم نفسها في لوحة Vercel عند النشر:

| المتغير | مطلوب؟ | الوضع | مثال القيمة | الغرض |
|---|---|---|---|---|
| `DATABASE_URL` | نعم — دائمًا | محلي + إنتاج | `file:/home/z/my-project/db/custom.db` محليًا، أو `libsql://library-اسم-حسابك.turso.io` إنتاجًا | مسار ملف SQLite محليًا، أو رابط قاعدة Turso السحابية |
| `DATABASE_AUTH_TOKEN` | نعم في الإنتاج | إنتاج | الرمز الناتج من `turso db tokens create library` | مصادقة الاتصال بقاعدة Turso (يُترك فارغًا محليًا) |
| `SESSION_SECRET` | إلزامي في الإنتاج | محلي + إنتاج | ناتج `openssl rand -hex 32` | مفتاح توقيع الجلسات وتجزئتها — بدونه تبقى الجلسات غير آمنة (القيمة الافتراضية للتطوير فقط) |
| `NEXT_PUBLIC_SITE_URL` | يُنصح به | إنتاج | `https://مكتبتك.com` | العنوان العام للموقع (بدون شرطة ختامية): روابط المشاركة وOpen Graph وsitemap |
| `S3_ENDPOINT` | اختياري | إنتاج | `https://معرف-حسابك.r2.cloudflarestorage.com` | نقطة نهاية تخزين Cloudflare R2 — مع بقية مفاتيح S3 يفعّل التخزين السحابي |
| `S3_BUCKET` | اختياري | إنتاج | `library-media` | اسم حاوية الملفات في R2 |
| `S3_ACCESS_KEY_ID` | اختياري | إنتاج | مفتاح Access Key ID من R2 API Token | تعريف مفتاح مصادقة التخزين |
| `S3_SECRET_ACCESS_KEY` | اختياري | إنتاج | Secret Access Key المقابل للمفتاح نفسه | سر مصادقة التخزين |
| `CRON_SECRET` | يُنصح به في الإنتاج | إنتاج | ناتج `openssl rand -hex 24` | حماية نقطة النشر المجدول `/api/cron/publish` — بدونها النقطة معطلة |

**قاعدة الوضعين:** متغيرات `S3_*` الأربعة إن تُركت فارغة يعمل الموقع بالتخزين المحلي تلقائيًا (مناسب للتطوير؛ القرص مؤقت على الاستضافة السحابية).

**لا تضع أي مفتاح أو سر في الكود أو في ملفات الواجهة الأمامية** — متغيرات البيئة فقط، وملف `.env` مستثنى تلقائيًا في `.gitignore` فلا يُرفع إلى GitHub أبدًا.

## إنشاء قاعدة البيانات محليًا

```bash
# المخطط موجود مسبقًا في prisma/schema.prisma
bun run db:push        # ينشئ/يحدّث جداول SQLite المحلية وفق المخطط
# اختياري عند تغيير المخطط مستقبلًا: bun run db:migrate
```

الجداول: `User, Session, Category, Tag, Book, BookTag, BookImage, MediaFile, SiteSetting, Page, Favorite, Order, OrderItem, AuditLog, ContactMessage, SiteVisit` — بعلاقات وقيود صحيحة وتواريخ إنشاء/تعديل ومعرفات ثابتة (cuid) لكل كتاب.

عند أول تشغيل تُزرع تلقائيًا: الإعدادات الافتراضية (قابلة للتعديل بالكامل من اللوحة) وأربع صفحات سياسات بمحتوى حقيقي. **لا تُزرع أي كتب أو بيانات تجريبية.**

> نفس المخطط هذا هو الذي يُرفع لاحقًا إلى Turso في خطوة النشر — لا يوجد مخطط مختلف للإنتاج.

## إنشاء أول حساب مالك (بطريقة آمنة)

1. شغّل الموقع وافتح `#/admin` (أو رابط «لوحة المطوّر» أسفل الفوتر).
2. بما أنه لا يوجد أي مستخدم، تظهر شاشة إنشاء **«حساب المالك الأول»**.
3. أدخل الاسم والبريد وكلمة مرور قوية (10 أحرف على الأقل) — تُخزَّن مشفّرة بـ scrypt.
4. تُنشأ الجلسة تلقائيًا وتفتح اللوحة بصلاحية **OWNER**.

هذه البوابة (المسار `POST /api/admin/bootstrap`) تعمل **فقط** ما دام عدد المستخدمين صفرًا؛ بعدها تختفي نهائيًا ولا يمكن استغلالها — **لا حسابات افتراضية في الكود**. يمكن للمالك لاحقًا إضافة محررين من قسم «المستخدمون».

## دليل الاستخدام السريع

1. **الهوية أولًا**: الإعدادات → هوية الموقع (اسم المكتبة/المؤلف/العبارة/النصوص) → الشعار والبورتريه → الألوان (أو استعادة الافتراضية) → التواصل والسوشال.
2. **التصنيفات**: أضفها يدويًا أو من الاقتراحات السريعة (روايات، دينية وفكرية…). لا يظهر للزائر إلا التصنيف الذي فيه كتاب منشور.
3. **أول كتاب**: الكتب → كتاب جديد → العنوان (يولّد الرابط تلقائيًا) → الوصف والبيانات → ارفع الغلاف → **حفظ كمسودة** → **معاينة** → عند الجاهزية: **نشر**.
4. **الجدولة**: اختر حالة «مجدول» وحدد التاريخ والوقت — يُنشر تلقائيًا عند حلول الموعد (انظر [النشر المجدول للكتب](#النشر-المجدول-للكتب-كسول-تلقائي--cron-يومي)).
5. **القراءة الرقمية**: ارفع PDF وأفعّل «القراءة داخل الموقع»، وفعّل «السماح بالتنزيل» إن رغبت.
6. **المتجر** (لاحقًا): الإعدادات → تفعيل المتجر + العملة → فعّل البيع في كل كتاب → تابع الطلبات من قسمها.
7. **المفضلة وحسابات القراء**: فعّل «تسجيل القراء» ليظهر نموذج الحساب الجديد.

## النشر الدائم المجاني خطوة بخطوة (GitHub + Turso + R2 + Vercel)

المعمارية المزدوجة تجعل النشر مجانيًا بالكامل: قاعدة بيانات SQLite سحابية (**Turso**) وتخزين ملفات سحابي (**Cloudflare R2**) واستضافة (**Vercel**) ومستودع كود (**GitHub**) — والكود نفسه الذي يعمل محليًا هو الذي يعمل في الإنتاج.

| الخدمة | الدور | الخطة المجانية |
|---|---|---|
| GitHub | مستودع الكود (خاص يكفي) | مجانية |
| Turso | قاعدة بيانات SQLite سحابية | حتى 500 قاعدة و9GB تخزين وقراءة سطور بسخاء يفوق حاجة مكتبة |
| Cloudflare R2 | تخزين الملفات (متوافق S3) | 10GB مجانًا بلا رسوم خروج |
| Vercel | الاستضافة والنشر التلقائي | خطة Hobby المجانية — وتسمح بالمهام المجدولة اليومية |

> **مبدأ الوضعين:** قاعدة البيانات (ملف SQLite محليًا / Turso إنتاجًا) والتخزين (`private-uploads/` محليًا / R2 إنتاجًا) يتحولان من متغيرات البيئة وحدها. المخطط واحد لأن كليهما SQLite عبر محوّل `@prisma/adapter-libsql` (ممكّن في `prisma/schema.prisma` بـ `previewFeatures = ["driverAdapters"]`)، ونموذج الأمان واحد في الوضعين.

### الخطوة 1 — ارفع المشروع إلى GitHub

```bash
git init
git add .
git commit -m "مكتبة المؤلف — جاهزة للنشر"
# أنشئ مستودعًا على github.com (خاص يكفي تمامًا) ثم اربطه وارفع:
git remote add origin git@github.com:اسم-حسابك/اسم-المستودع.git
git push -u origin main
```

- ملف `.env` مستثنى تلقائيًا في `.gitignore` (وكذلك قاعدة `db/custom.db` المحلية ببياناتها) — أسرارك لا تُرفع.
- ملف `.env.example` يُرفع **عمدًا** كمرجع لأسماء المتغيرات دون أي قيم سرية.

### الخطوة 2 — قاعدة البيانات السحابية Turso

```bash
# 1) ثبّت أداة Turso CLI
curl -sSfL https://get.tur.so/install.sh | bash

# 2) أنشئ حسابًا مجانيًا (أو سجّل عبر الموقع turso.tech)
turso auth signup

# 3) أنشئ قاعدة البيانات
turso db create library

# 4) اجلب رابط الاتصال — هذه هي قيمة DATABASE_URL
turso db show library --url
#    ← libsql://library-اسم-حسابك.turso.io

# 5) اجلب رمز المصادقة — هذه هي قيمة DATABASE_AUTH_TOKEN
turso db tokens create library

# 6) ادفع مخطط Prisma إلى Turso (أمر مُختبر ويعمل)
npx prisma migrate diff --from-empty --to-schema-datamodel prisma/schema.prisma --script > schema.sql
turso db shell library < schema.sql
```

- احتفظ بناتج الخطوتين 4 و5 — ستُدخلهما في Vercel بعد قليل.
- الخطة المجانية (حتى 500 قاعدة و9GB تخزين وقراءة سطور بسخاء يفوق حاجة مكتبة) تكفي وأكثر.

### الخطوة 3 — تخزين الملفات Cloudflare R2

القرص على الاستضافة السحابية مؤقت، لذا نحتاج تخزينًا دائمًا للملفات (الأغلفة، الصور، PDF):

1. من لوحة Cloudflare: **R2 → Create Bucket** — مثال للاسم: `library-media`.
2. Endpoint الخاص بحسابك بصيغة: `https://معرف-حسابك.r2.cloudflarestorage.com`.
3. من **Manage R2 API Tokens → Create API Token** بصلاحية **Object Read & Write** على الحاوية — يُنشئ لك Access Key ID وSecret Access Key.

القيم الأربع الناتجة توضع في المتغيرات: `S3_ENDPOINT` و`S3_BUCKET` و`S3_ACCESS_KEY_ID` و`S3_SECRET_ACCESS_KEY`.

> **الأمان محفوظ في الوضعين**: كل الملفات تُقدَّم حصرًا عبر `/api/media/[id]` مع فحص الصلاحيات على الخادم — PDF الخاصة لا تُكشف أبدًا برابط مباشر. لذا **لا حاجة لجعل الحاوية عامة**؛ أبقها خاصة.

> إن تُركت متغيرات S3 فارغة يعمل الوضع المحلي تلقائيًا — يمكنك البدء بدون R2 والاتصال به لاحقًا (انظر [الأسئلة الشائعة](#أسئلة-شائعة-عند-النشر)).

### الخطوة 4 — النشر على Vercel

1. سجّل في vercel.com بحساب GitHub → **Add New → Project** → اختر مستودع المكتبة.
2. الإعدادات تُكتشف تلقائيًا (Next.js + Bun من `bun.lock`) — **اترك أمر البناء افتراضيًا**؛ سكربت `postinstall` يشغّل `prisma generate` تلقائيًا.
3. افتح **Environment Variables** وأضف (القيم من الخطوتين 2 و3):

| المتغير | القيمة |
|---|---|
| `DATABASE_URL` | رابط libsql من `turso db show library --url` |
| `DATABASE_AUTH_TOKEN` | الرمز من `turso db tokens create library` |
| `SESSION_SECRET` | ناتج `openssl rand -hex 32` — **إلزامي في الإنتاج** |
| `NEXT_PUBLIC_SITE_URL` | `https://نطاقك` — يُستخدم في روابط المشاركة وOpen Graph |
| `S3_ENDPOINT` | `https://معرف-حسابك.r2.cloudflarestorage.com` |
| `S3_BUCKET` | `library-media` |
| `S3_ACCESS_KEY_ID` | مفتاح الوصول من R2 |
| `S3_SECRET_ACCESS_KEY` | المفتاح السري من R2 |
| `CRON_SECRET` | ناتج `openssl rand -hex 24` |

```bash
# توليد السرين:
openssl rand -hex 32   # SESSION_SECRET
openssl rand -hex 24   # CRON_SECRET
```

4. اضغط **Deploy** — بعد قليل تحصل على رابط `اسم-المشروع.vercel.app` يعمل بشكل كامل.

### الخطوة 5 — أنشئ حساب المالك الأول

- افتح الموقع المنشور → رابط «لوحة المطوّر» أسفل التذييل (أو أضف `#/admin` إلى الرابط).
- بما أن قاعدة البيانات جديدة وفارغة، تظهر شاشة إنشاء **«حساب المالك الأول»** — أدخل الاسم وبريدًا حقيقيًا وكلمة مرور قوية (10+ أحرف).
- هذه الشاشة تختفي نهائيًا بعد إنشاء الحساب: المسار `POST /api/admin/bootstrap` يعمل فقط عند صفر مستخدمين — **لا حسابات افتراضية في الكود**.
- بعد الدخول: إعدادات الموقع كلها (اسم المكتبة، اسم المؤلف، الشعار، الألوان، النصوص، روابط التواصل) تُدار من لوحة الإدارة دون لمس الكود.

### الخطوة 6 — اربط نطاقك الخاص (اختياري)

- في Vercel: **Settings → Domains** → أضف نطاقك واتبع تعليمات DNS.
- التكلفة الوحيدة هي النطاق نفسه (~5–15 دينار سنويًا)؛ الاستضافة وقاعدة البيانات والتخزين مجانية ضمن حدود خططها.
- بعد الربط حدّث `NEXT_PUBLIC_SITE_URL` إلى `https://نطاقك` (ضروري لروابط المشاركة وOpen Graph).
- بدون نطاق خاص، رابط `اسم-المشروع.vercel.app` يعمل بشكل كامل.

## النشر المجدول للكتب (كسول تلقائي + Cron يومي)

تعمل الجدولة بطبقتين، دون أي إعداد منك:

1. **الآلية الكسولة**: عند أي زيارة للموقع تُنشر تلقائيًا الكتب التي حان موعدها المجدول — الدالة `publishDueBooks()` تعمل قبل استعلامات الكتب العامة.
2. **ضمانة Cron اليومية**: ملف `vercel.json` يشغّل نقطة `/api/cron/publish` يوميًا الساعة **03:00 UTC** — لضبط النشر في موعده حتى لو لم يزر أحد الموقع. خطة Hobby المجانية تسمح بالمهام المجدولة اليومية.

**الحماية بالسر**: النقطة تتطلب `CRON_SECRET` في البيئة وتقبل الطلب فقط إذا حمل ترويسة `Authorization: Bearer <الرمز>` — وهو ما ترسله Vercel Cron تلقائيًا. للتشغيل اليدوي (اختبار بعد النشر):

```
https://نطاقك/api/cron/publish?secret=الرمز
```

## الأمان والخصوصية

- تسجيل دخول آمن: كلمات مرور scrypt (salt لكل مستخدم)، جلسات عشوائية 256-bit مخزنة مُجزّأة (SHA-256 + pepper من `SESSION_SECRET`) في القاعدة مع صلاحية 30 يومًا وكوكي httpOnly/SameSite=Lax/Secure في الإنتاج.
- **التحقق من الصلاحيات على الخادم في كل مسار API** (مالك/محرر/قارئ) — إخفاء الروابط ليس الحماية الوحيدة.
- رفع الملفات: قائمة أنواع مسموحة (JPG/PNG/WebP/GIF/PDF) + حدود حجم (8MB صور / 25MB PDF) + **تحقق البصمة السحرية (magic bytes)** + أسماء تخزين عشوائية (UUID) تمنع اجتياز المسار.
- الملفات الخاصة (مثل PDF) تُخدم عبر `/api/media/[id]` فقط: العامة للجمهور، والخاصة للمشرفين أو لقراءة كتاب منشور مفعّلة قراءته، والتنزيل يتطلب تفعيله صراحة. **لا يُكشف مسار التخزين الأصلي أبدًا** — سواء خُزِّن الملف على القرص المحلي أو في R2، والحاوية السحابية تبقى خاصة.
- المسودات والمخطوطات غير المنشورة خاصة بالمالك افتراضيًا ولا تظهر للزوار ولا في خرائط البحث.
- حماية النماذج من المدخلات الضارة (تنقية محارف التحكم، تحقق أنواع وأطوال) وسجل تدقيق لكل عملية إدارية مهمة (AuditLog).
- الأسرار في متغيرات البيئة فقط. سياسة خصوصية حقيقية منشورة تصف ما يجمعه الموقع فعليًا.
- حدود معروفة: منع التنزيل/النسخ داخل قارئ الويب ليس حماية مطلقة للمحتوى الرقمي (مذكور ذلك بشفافية في صفحات الموقع نفسها).

## الاختبارات الأساسية المطبقة

أثناء التطوير جرى التحقق من:

1. **حماية اللوحة**: زائر بلا جلسة → 401/شاشة دخول على كل مسارات `/api/admin/*`؛ قارئ مسجل → 403 «غير مصرح»؛ مسارات المالك فقط (المستخدمون/حفظ الإعدادات) → محرر يُرفض 403.
2. **المسودة لا تظهر للعامة**: كتاب بحالة DRAFT → غائب عن `/api/books` و`/api/books/detail` وصفحته تُرجع 404 للزائر، بينما تظهر للمالك مع `preview=1` مع شارة «معاينة إدارية».
3. **إضافة ونشر كتاب من اللوحة**: إنشاء مسودة → لا تظهر publicly → نشر → تظهر في القائمة والرئيسية ويُولّد رابط `/?book=slug` بعنوان ووصف وOG صحيحين وصفحة عامة سليمة، ثم يُحذف زخرف الاختبار.
4. **حماية الملفات الخاصة**: PDF غير مرتبط بكتاب قابل للقراءة → 403 للزائر و200 للمشرف؛ التنزيل بلا تفعيل → مرفوض.
5. **التحقق من المدخلات**: عناوين مكررة (409)، نشر مجدول بلا موعد مستقبلي (400)، بريد/عملة/لون غير صالحين (400)، وحذف تصنيف عليه كتب (409).
6. **المتجر المعطل**: طلب شراء → 403 «المتجر غير مفعّل»، ولا يظهر أي سعر/زر شراء للزائر.

## أسئلة شائعة عند النشر

### تظهر صفحة خطأ «DATABASE_URL غير مضبوط» بعد النشر؟
المتغير غير موجود (أو فارغ) لدى Vercel. أضف في **Environment Variables**: `DATABASE_URL` برابط libsql من `turso db show library --url`، و`DATABASE_AUTH_TOKEN` برمز `turso db tokens create library`، ثم أعد النشر (Redeploy). محليًا: تأكد من نسخ `.env.example` إلى `.env` وضبط `DATABASE_URL="file:…"`.

### نسيت ضبط SESSION_SECRET؟
هو **إلزامي في الإنتاج** — بدونه تبقى الجلسات غير آمنة (القيمة الافتراضية للتطوير فقط). أنشئه بـ `openssl rand -hex 32`، أضفه في Vercel، وأعد النشر. ملاحظة: إن غيّرته لاحقًا ستُبطل الجلسات القائمة ويُطلب من الجميع تسجيل الدخول من جديد.

### الصور والأغلفة لا تظهر على Vercel؟
على الأرجح متغيرات `S3_*` فارغة: القرص على الاستضافة السحابية **مؤقت**، فالوضع المحلي مناسب للتطوير فقط. أكمل إعداد R2 (الخطوة 3) وأدخل المتغيرات الأربعة في Vercel وأعد النشر، ثم ارفع الملفات مجددًا من لوحة الإدارة — الملفات التي رُفعت قبل ذلك على قرص زائل تكون قد فُقدت مع إعادة النشر.

### الكتب المجدولة لم تُنشر في موعدها؟
النشر الكسول يحدث عند أول زيارة بعد حلول الموعد، والـ Cron اليومي (03:00 UTC) ضمانة إضافية. تأكد أن حالة الكتاب «مجدول» بتاريخ ووقت مستقبليين، وأن `CRON_SECRET` مضبوط لدى Vercel. للتشغيل الفوري: افتح `/api/cron/publish?secret=الرمز`.

### كيف أنقل بياناتي من بيئة التطوير إلى الإنتاج؟
القاعدتان SQLite، فيمكن تصدير بياناتك المحلية وتطبيقها على Turso (على قاعدة **فارغة جديدة** لأن التصدير يشمل المخطط والبيانات معًا):

```bash
sqlite3 db/custom.db .dump > data.sql
turso db shell library2 < data.sql   # ثم وجّه Vercel إلى القاعدة الجديدة
```

ثم ارفع الملفات (أغلفة/PDF) مجددًا من لوحة الإدارة لتُخزَّن في R2.

### هل أستطيع البدء بدون R2؟
نعم — متغيرات S3 اختيارية، وإن تُركت فارغة يعمل التخزين المحلي تلقائيًا بنفس الأمان. لكن على Vercel القرص مؤقت والملفات تُفقد مع كل إعادة نشر، فضبط R2 قبل رفع الغلاف والملفات الفعلية هو الأسلم.

### متى أدفع مقابل أي شيء؟
كل ما في هذا الدليل مجاني: GitHub (مستودع خاص)، Turso (الخطة المجانية)، R2 (10GB بلا رسوم خروج)، Vercel (خطة Hobby). الدفع الوحيد شبه المؤكد هو النطاق الخاص (~5–15 دينار سنويًا)، ولا تظهر تكاليف أخرى إلا إذا تجاوزت حدود الخطط المجانية (تخزين أو حركة استخدام كبيرة جدًا).

### كيف أحذف كل شيء وأبدأ من جديد؟
أنشئ قاعدة Turso جديدة (`turso db create library2`)، ارفع إليها `schema.sql` (من خطوة الدفع)، حدّث `DATABASE_URL` و`DATABASE_AUTH_TOKEN` في Vercel وأعد النشر — القاعدة الفارغة ستعيد ظهور شاشة «حساب المالك الأول». يمكن تفريغ ملفات R2 من لوحة Cloudflare، وحذف القاعدة القديمة من حسابك في Turso عند التأكد من عدم الحاجة إليها.
